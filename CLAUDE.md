`PLANNING.md` is the full specification (§15 holds the user's decisions and wins over earlier sections). `GUIDE.md` /

## Mission
Turn each Vallis chapter into **one learning package** that makes the chapter *click* for a first-time reader with
first-year calculus and **no climate background** (and for Shammunul, working through the book for a PhD in climate
dynamics). Same four deliverables per chapter as fluidpy, same formats, same quality bar, plus 3-D, movies and real data:

| Per chapter | What it is |
|---|---|
| `notebooks/chNN_<slug>.ipynb` | The teaching notebook, **executed**: plain words → step-by-step maths (derivations one move per step) → tiny worked example (easy \| exact numbers) → **from-scratch Python for every computable equation** + the `fluidpy` call + an `assert` that they agree → figure → how to read it; K-recaps of Kundu material; mechanism 🌍 and reading 🗺️ cards; explainers, scenes and movies embedded |
| `notebooks/chNN_<slug>_colab.ipynb` | The Colab twin (outputs stripped; setup cell installs the pinned `fluidpy` tag and loads committed derived data, **no keys needed**) |
| `notebooks/chNN_<slug>.html` | The published page: every explainer and scene a full-window block, Colab button, movies (after approval), data credits |
| `viz/chNN/<slug>.html` (**5–14**; Ch. 0 about 12 per part, soft) | Explainers in the **unchanged Kundu format** (`interactive-viz`), with three.js 3-D as one linked view where the third dimension helps |
| `scenes/chNN/<slug>.html` (0–4; Ch. 0 up to 6) | Standalone full-window three.js scenes for dense ideas (PLANNING §15.1) |
| `figs/chNN/fig_NN_MM.py` | The book's data figures **rebuilt by our code from open data**, each with a reading card |
| movies (1–3 × 2–3 min, async) | Remotion + Kokoro (`af_bella`, speed 1.0) motion graphics, published in `shammun/aofd-media` only after the user approves |

## Session start (read first)
The SessionStart hook prints `tools/progress.py --brief`. **If it shows "WAITING FOR THE USER"**
(`progress.json → setup.s11_poc` is not `approved`), the first reply of the session must be: a short status update
(what is done, PoC A–G states, disk on C:/G:), the "what to open" list, and the open questions from
`progress.json → setup.awaiting_user` — then **stop and wait for the user's answers**. Do not start `/do-chapter`,
release fluidpy, or publish anything until the user has answered. After the answers: record the verdict
(`setup.poc`, `knowledge/*_patterns.md` PoC records, PLANNING §15), apply the requested fixes through the owning
agents, set `setup.s11_poc` to `approved` and remove `setup.awaiting_user`.

## One command
`/do-chapter N` runs the pipeline (PLANNING §6: preflight → analyze ∥ scout → curate → crossref → design ∥ implement ∥
data → verify → review ∥ viz/viz3d ∥ figures ∥ notebook → knowledge ∥ library ∥ publish → push). `/make-movies N` runs
the movie phase asynchronously; `/approve-movie N slug` publishes one. `/status` says where things are, the fluidpy
pin, data accounts, and **free space on C: and G:**.

## Non-negotiable rules
1. **Sequential chapters.** Chapter N starts only when N−1 has `publish: pass` and `knowledge: done` (or the user
   overrides). Agents read `knowledge/CUMULATIVE.md`, `notation.md`, `viz_patterns.md` (and `kundu_index.yaml`) first.
   **No chapter may assume anything Chapter 0 or an earlier chapter has not explained.**
2. **Equations come from page images.** `chapters/chNN.txt` garbles maths. Render the page
   (`.venv/Scripts/python.exe tools/render_pages.py chNN --eq 2.12`) and read the PNG before transcribing, coding or
   displaying an equation. Kundu equations (K-recaps, Chapter 0A) come from Kundu page images rendered in
   `../Fluid Dynamics` (read-only) or `_private/Kundu_AppendixB_Mathematical_Tools.pdf`. Never code from memory.
3. **Teach in Shammunul's style** (`teaching-style`): CORE blocks with plain words first; derivations never skipped (one
   move per step: did · line · why · in words; check; meaning); **show the equation, not just its number** — Vallis
   `(2.12)`, Kundu `(K 13.15)`, always with the maths beside them; anatomy strip + magnitude bars for balances; Like… /
   Unlike… for analogies; "clockwise" only with hemisphere and viewpoint; easy | exact numbers; every climate word
   defined on first use from `knowledge/glossary.yaml`, every symbol from `knowledge/symbols.yaml`. Chapter 0 and the
   plain-words parts use the **informal blog-like voice** (§1d of `teaching-style`): no "clearly"/"obviously".
4. **From scratch, then the library** (`from-scratch-code`): every computable numbered equation gets a scratch cell
   (inputs with units, one operation per line, a novice comment per line, no hidden library call) followed by the
   `fluidpy` call and `np.testing.assert_allclose(scratch, lib, rtol=…)` with the tolerance justified. Parity is
   pedagogy, not evidence: library evidence comes from the V-ladder.
5. **Explainers in the Kundu format; 3-D inside it** (`interactive-viz` §0, `viz3d`): one self-contained HTML, question
   title, linked views on one state and one clock, presets, transport, status; tabs Walkthrough (4–8) · Explore ·
   Explain (≥ 3 numbered sections) · Derivation · Equations · Code · Check yourself (≥ 3); ≥ 2 depth features;
   `selftest()` parity rows; **no scrolling** at 360×640 … 1920×1080 and in a notebook frame; no text below 12 px.
   three.js 0.186.1 via the import map, lazy, disposable, context-loss safe, `Viz.proj3` fallback; audited with
   `tools/shot.py --3d`. The curator decides 3-D per explainer ("earn the third dimension") and dense ideas become a
   standalone scene; explainer ↔ scene link both ways. No jet/rainbow colour maps (except the labelled bad example).
6. **Traceable physics and honest visuals.** Every library function's docstring cites Vallis § + equation (and
   "Kundu: K§/eq" if shared), symbols with SI units, assumptions, validation label. Every moving or coloured thing traces
   to a tested function or a cited dataset; exaggerations labelled ("not to scale", "vertical ×1000"); pseudo-data only
   when nothing open exists, stamped **"ILLUSTRATIVE — synthetic data"**.
7. **Evidence proportional to importance** (`verify-implementation`): computable CORE ≥ 2 independent levels; every
   called function ≥ 1. Never loosen a tolerance to pass; ≤ 3 fix loops, then report. **The full fluidpy suite (all
   Kundu chapters) must stay green on every library change.**
8. **Subagents do the work; the main session orchestrates.** Agents never commit; the orchestrator commits after each
   phase (`chNN: <phase> — <one line>`). Never run two agents that write the same folder at the same time.
9. **Reuse before re-implementing.** `kundu_index.yaml`, `fluidpy.core` (never change a `core` signature: the Kundu
   notebooks import them), `assets/viz_lib.js`, `viz3d.js`, `knowledge/viz_patterns.md`. Only the orchestrator or the
   knowledge-keeper edits shared JS; then `tools/viz_inline.py --all`.
10. **The repos are public; the books are not.** Never commit or publish book text, page images, crops, transcribed
    tables or exercises — Vallis or Kundu. Figures are regenerated by our code ("the science, not the artwork");
    movies have no book scans. `tools/check_secrets.py` + `tools/check_public.py` run before every push
    (`.githooks/pre-push`). **Never read the Kundu site's files with intent to edit: the AOFD session changes only
    `fluidpy/`, `tests/`, `pyproject.toml`, `CHANGELOG.md` in `../Fluid Dynamics`** (hooks enforce it).
11. **Data and disk** (PLANNING §15.2, §15.4). Every download goes through `fluidpy.data.fetch()` →
    `tools/disk_guard.py`: G: floor 50 GB free and project data cap 150 GB, C: floor 40 GB. If G: is missing, stop
    (never fall back to C:). Download subsets, reduce at once, evict only registry-tracked re-downloadable raw files whose
    derived product exists (logged in `logs/evictions.log`). **Report free space on C: and G: before and after every
    download, render, install and phase.** Credentials stay in `%USERPROFILE%` and Windows Credential Manager (service
    `aofd`) — never in a repo, notebook, report or memory file.
12. **Windows host, path with spaces.** Quote paths; `pathlib`; `.venv/Scripts/python.exe`; `python -m nbconvert`;
    kernel `aofd-venv`; TTS in `.venv-tts`; OPeNDAP via `engine="pydap"`; write code files with Write/Edit (heredocs
    mangle backslashes). Long commands go in `tools/*.py`.
13. **Outward-facing actions** (`gh repo create`, enabling Pages, first pushes, pushing fluidpy tags, publishing a
    movie) — ask the user, or have them run the exact command with `!`. Never force-push. Movies go public only after
    `/approve-movie`.
14. **Never hand back placeholders.** No agent returns while a run is in progress; report real numbers.
