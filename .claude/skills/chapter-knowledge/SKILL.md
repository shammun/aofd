# chapter-knowledge — make chapter N+1 smarter than chapter N

## Read at chapter start (every agent, in this order)
1. `knowledge/CUMULATIVE.md` — Kundu summary + the Vallis pipeline so far, library functions, validation summary,
   pitfalls, explainer/scene/movie/figure inventory.
2. `knowledge/notation.md` (Kundu ↔ Vallis crosswalk, sign conventions) and `knowledge/symbols.yaml` (the atlas: symbol,
   name, say_it, unit, typical Earth values, meaning, first use, aka, pitfall, see); `knowledge/glossary.yaml` (every
   climate word in plain language, with first use); `knowledge/primers.md` (concepts and tools already primed).
3. `knowledge/kundu_index.yaml` (generated by `tools/kundu_index.py`; never edited by hand) — Kundu concept ids,
   derivations with step counts, notebook anchors, explainer metas, fluidpy functions, site URLs.
4. `knowledge/viz_patterns.md` (2-D **and** 3-D sections), `knowledge/data_patterns.md` (datasets, routes, pitfalls,
   licences, sizes), `knowledge/movie_patterns.md` (render times, sizes, pacing, voice, what the user liked).
5. `knowledge/concept_map.md`; `knowledge/ch<N-1>.md` → "Feeds forward".

## Write at chapter end: `knowledge/chNN.md`
```
# Chapter N — <title>   (completed <date>, commit <hash>, fluidpy <tag>)
## 1. What clicked — the teaching spine (our words, each with its equations written out + numbers)
## 2. Implemented items (concept → fluidpy target (geo/diag/data) or aofd glue → Vallis §/eq → validation label → tier)
## 3. K-recaps given (K id → Kundu § / derivation → where re-taught) and what Vallis added
## 4. New reusable functions and JS helpers (signature + one line + who will reuse)
## 5. Mathematics → Python lessons (only NEW pitfalls)
## 6. Conventions used (latitude, ψ sign, lapse-rate sign, b vs ρ′, units) and changes vs earlier chapters
## 7. Results vs benchmarks; data figures with their checked numbers
## 8. Explainers, 3-D scenes, movies (slug · idea · what worked · what the reviewer / user flagged)
## 9. Data used (registry keys, sizes on G:, derived products committed, disk before/after)
## 10. Feeds forward — what later chapters need from this one
## 11. Open questions / revisit
```

## Update the shared files
- `CUMULATIVE.md` (rewrite, ≤ ~450 lines): pipeline diagram · library table (geo/data/diag, labels) · inventories
  (explainers, scenes, movies, figures) · global pitfalls · benchmark inventory · validation summary per chapter.
- `concept_map.md`: `| Concept | Vallis § / eq | Kundu link (if K) | fluidpy target | Label | Tier | Taught in | Verified in |`;
  never delete a verified row.
- `notation.md` + `symbols.yaml`: every symbol the chapter uses; ⚠️ flag where Vallis differs from Kundu or common
  practice ("Which convention?"). `viz/atlas.html` is regenerated from `symbols.yaml` by `tools/build_site.py`.
- `glossary.yaml`: every climate word the analyst listed (plain words, ≤ 25 words, first use, see-also).
- `primers.md`: one row per primer (`| Term | Explained in (chNN · § · id) | Gist |`).
- `viz_patterns.md`: patterns that worked / failures and fixes / promotion candidates / ideas for later — with a **3-D
  section** (camera presets, layers, perf numbers GPU vs SwiftShader, context counts) and the PoC verdicts.
- `data_patterns.md`: per dataset key — route, size, licence verdict, pitfalls (lat N→S, flux signs, 403s, pydap).
- `movie_patterns.md`: render wall time, fps, size, GPU/SwiftShader, TTS quirks and lexicon entries, the user's notes.

## Promotion (only when the orchestrator's brief allows it — nothing else may be reading `viz/`, `scenes/` at the time)
- JS helper duplicated in ≥ 2 explainers → `assets/viz_lib.js`; 3-D layer or glyph duplicated in ≥ 2 scenes →
  `assets/viz3d.js` (documented, backwards compatible) → `tools/viz_inline.py --all` → `tools/shot.py
  templates/viz_example.html --quick`, `tools/shot.py --3d templates/viz_example_globe.html --quick` and
  `--chapter <each affected> --quick` must PASS, else revert.
- Python helper used by ≥ 2 chapters → `fluidpy.geo/diag` (via the implementer brief, skill `fluidpy-library`), with
  re-exports; full fluidpy pytest green. Book-specific glue stays in `aofd/`.
- A lesson that applies to any chapter → the relevant skill's "Lessons" section (one line, tagged with the chapter).
- House movie components (`movies/src/house/*.tsx`) are promoted the same way, never edited by a motion-builder.

## progress.json
The knowledge-keeper sets `knowledge: "done"` + notes for its chapter; the orchestrator owns every other key,
`current_chapter`, `library_pin` and all commits.
